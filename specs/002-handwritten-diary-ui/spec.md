# Feature Specification: 手書きの絵日記帳風 UI

**Feature Branch**: `002-handwritten-diary-ui`

**Created**: 2026-11-08

**Status**: Draft

**Input**: User description: "日記のUIを大きく改善したい。横書きに変更。マス目ではなく罫線にする。UIを手書き用フォーマットに近づけたい。フォントはなるべく手書きに近いようにする。画像のようなUIに近づけてみてほしい(参考画像: 角の丸い1枚のカードに、上から絵の枠、「月 日( )」の日付欄と右隣の欄、点線の罫線が並ぶ文章欄を配置した絵日記帳のページ)"

## 概要

001-picture-diary-service で作った絵日記の記入画面と表示を、紙の絵日記帳の1ページに近い見た目に作り替える。
文章は縦書きの原稿用紙(マス目)から、横書きの罫線入りの欄に変える。文字は手書きに近い書体で表示する。
保存する内容(画像、文章、日付、天気)と、公開範囲などの振る舞いは変えない。

参考画像のページ構成(上から順に):

1. 絵の枠(ページの上半分ほど)
2. 日付欄「〇月 〇日(〇)」と、その右隣の天気欄(参考画像の天気欄は空欄だが、日付の横で天気を入力できるようにする)
3. 点線の罫線が引かれた文章欄

ページ全体は、角の丸いカードとして画面に置く。

## Clarifications

### Session 2026-11-08

- Q: 罫線の行数は固定か、文章の量に合わせて増えるか? → A: 最初は8行で、文章の量に合わせて増える(400文字の上限は維持)
- Q: 手書き風の書体の雰囲気は? → A: ていねいなペン字風(大人の手書きのノート)
- Q: 参考画像の虹色の縁取りと四隅の白い弧を取り入れるか? → A: 取り入れない(角の丸い薄い灰色の紙と黒い枠線のみ)
- Q: 参考画像にない天気の入力をどこに置くか? → A: 日付欄の横(同じ行の右隣の欄)で天気を入力し、表示する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 絵日記帳のページに書くように記入する (Priority: P1)

利用者は、紙の絵日記帳の1ページのような記入画面で、絵の枠に画像を入れ、日付欄で日付と天気を選び、罫線の上に横書きで文章を書く。

**Why this priority**: 記入は毎日使う中心の操作で、今回の改善の目的そのものである。記入画面だけでも「手書きの絵日記帳に書く」体験を提供できる。

**Independent Test**: ログイン後に記入画面を開き、ページの構成(絵の枠、日付欄、罫線の文章欄)が参考画像の順に並び、文章が横書きで罫線の上に並ぶことを確認し、保存できることを確かめる。

**Acceptance Scenarios**:

1. **Given** ログイン中の利用者, **When** 絵日記の記入を始める, **Then** 上から絵の枠、日付欄、罫線の文章欄の順に並んだ1枚のページが表示され、日付欄には当日の月、日、曜日が入っている
2. **Given** 記入画面, **When** 画像を選ぶ, **Then** 選んだ画像が絵の枠の中に、縦横比を保ったまま表示される
3. **Given** 記入画面, **When** 文章を入力する, **Then** 文章は左から右へ横書きで進み、各行の文字が罫線の上に乗るように並ぶ
4. **Given** 文章が1行に収まらない記入画面, **When** 入力を続ける, **Then** 次の罫線の行へ折り返し、文字と罫線の位置がずれない
5. **Given** 8行を超える文章を入力中の記入画面, **When** 9行目に進む, **Then** 罫線の行が増えてページが縦に伸び、すべての文章が見えたまま入力を続けられる
6. **Given** 記入画面, **When** 日付欄の横の天気欄で天気を選ぶ, **Then** 選んだ天気がその欄に表示され、ほかの天気は選ばれていない状態になる
7. **Given** 画像、文章、または天気が未入力の記入画面, **When** 保存しようとする, **Then** 保存されず、不足している項目が示される(001 と同じ)

---

### User Story 2 - 書いた絵日記を同じページの見た目で読む (Priority: P1)

利用者とフォロワーは、保存された絵日記を、記入画面と同じ絵日記帳のページの見た目で読む。

**Why this priority**: 書いたときと同じ見た目で読めないと、手書きの絵日記帳としての体験が成り立たない。記入と同じく中心の機能である。

**Independent Test**: 保存済みの絵日記を開き、記入画面と同じページ構成と書体で、横書きの文章が罫線の上に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 保存済みの絵日記, **When** 本人が開く, **Then** 記入画面と同じページ構成で、絵、日付、曜日、天気、罫線の上の横書きの文章が表示される
2. **Given** 閲覧を許可されたフォロワー, **When** みんなの日記の一覧や相手のページで絵日記を見る, **Then** 同じページの見た目で表示される
3. **Given** 001 の縦書きの画面で保存した既存の絵日記, **When** 開く, **Then** 内容を変えずに、新しいページの見た目(横書き)で表示される

---

### User Story 3 - どの端末でも手書きらしい見た目で読み書きする (Priority: P2)

利用者は、スマートフォンでもパソコンでも、手書きに近い書体と絵日記帳のページの見た目で、横スクロールせずに読み書きできる。

**Why this priority**: 書体が端末ごとに変わると、手書きらしさが失われる。記入と表示が動いた上での品質の改善のため P2 とする。

**Independent Test**: 幅360pxの画面と幅1280pxの画面で記入画面と表示画面を開き、同じ手書き風の書体で表示され、ページが画面からはみ出さないことを確認する。

**Acceptance Scenarios**:

1. **Given** 幅360pxの画面, **When** 記入画面または表示画面を開く, **Then** ページ全体が画面の幅に収まり、横スクロールが起きない
2. **Given** 主要なブラウザ(Chrome、Safari、Firefox、Edge の最新版), **When** 絵日記を表示する, **Then** 文章と日付欄が同じ手書き風の書体で表示される
3. **Given** 手書き風の書体を読み込めない状況, **When** 絵日記を表示する, **Then** 読みやすい代わりの書体で表示され、文章は欠けずに読める

---

### Edge Cases

- 400文字いっぱいの文章や、改行を多く含む文章でも、罫線の行が足りずに文字が欄からはみ出したり、隠れたりしない。
- 手書き風の書体に含まれない文字(絵文字、記号、まれな漢字など)は、代わりの書体で表示し、文字が欠けたり四角(□)になったりしない。
- 縦長、横長、正方形など、どの縦横比の画像も、絵の枠からはみ出さず、ゆがまずに表示される。
- 画像を選ぶ前の絵の枠は空の枠として表示し、画像を選べる場所だと分かるようにする。
- 文字を大きく表示する設定(ブラウザの拡大200%)でも、文字と罫線の位置がずれず、内容が欠けない。
- ダークモードの端末でも、ページは紙らしい明るい色を保ち、文字と罫線が読める。
- 書体の読み込みに時間がかかっても、文章は代わりの書体で先に表示され、読み込み後に行の位置が大きくずれない。

## Requirements *(mandatory)*

### Functional Requirements

**ページの構成**

- **FR-001**: System MUST 記入画面と表示画面で、絵日記を角の丸い1枚のページ(カード)として表示し、上から「絵の枠」「日付欄と天気欄」「罫線の文章欄」の順に配置する。
- **FR-002**: System MUST 絵の枠をページの幅いっぱいに置き、画像を縦横比を保ったまま枠の中に収めて表示する。画像がないときは空の枠を表示する。
- **FR-003**: System MUST 日付欄に「〇月 〇日(〇)」の形式で月、日、曜日を表示し、年はページの外(見出しなど)に表示する。
- **FR-004**: System MUST 日付欄と同じ行の右隣に「天気」の見出しを付けた天気欄を置き、記入画面ではその欄の中で天気(晴れ、くもり、雨、雪)から1つを選べるようにする。表示画面では、その欄に選んだ天気を表示する。天気の選択を日付欄から離れた場所(ページの外など)に置いてはならない。
- **FR-005**: System MUST 記入画面で日付を選べるようにし、選んだ日付を日付欄の形式で表示する。日付の制約(未来の日付の拒否、1日1件)は 001 のとおりとする。

**文章欄**

- **FR-006**: System MUST 文章を左から右へ進む横書きで表示し、縦書きとマス目の表示はやめる。001 の FR-010(縦書き)はこの要件で置き換える。
- **FR-007**: System MUST 文章欄に点線の横罫線を等間隔に引き、文章の各行が罫線の上に乗るように並べる。行の折り返しや改行のあとも、文字と罫線の位置をそろえる。
- **FR-008**: System MUST 文章の上限を 001 と同じ400文字とし、残りの文字数を記入画面に表示する。
- **FR-009**: System MUST 文章欄に最初は8行の罫線を表示し、文章が8行を超えたら、文章の量に合わせて罫線の行を増やす(ページは縦に伸びる)。400文字の上限は変えない。表示画面でも、行数は8行と文章の行数の多いほうとする。

**書体と見た目**

- **FR-010**: System MUST 文章、日付欄、天気欄を、手書きに近い日本語の書体(ひらがな、カタカナ、常用漢字を含む)で表示する。書体の雰囲気は、ていねいなペン字風(大人の手書きのノート)とし、400文字の文章でも読みやすいものを選ぶ。
- **FR-011**: System MUST 手書き風の書体を、端末にその書体が入っていなくても表示できるよう、サービス自身から配信する。書体を取得するために外部のサービスへ利用者の閲覧情報を送ってはならない(憲章 III)。
- **FR-012**: System MUST 手書き風の書体にない文字は代わりの書体で表示し、文字を欠けさせない。
- **FR-013**: System MUST ページを、角の丸い薄い灰色の紙と黒い枠線だけで表示し、参考画像の外側にある虹色のグラデーションの縁取りと四隅の白い弧は取り入れない。
- **FR-014**: System MUST ページの地の色、枠線、罫線を、ライトモードとダークモードのどちらでも紙らしい配色で表示し、文字と背景のコントラスト比を4.5:1以上にする。

**適用範囲**

- **FR-015**: System MUST 新しいページの見た目を、記入画面、編集画面、絵日記の表示画面、みんなの日記の一覧、相手のページの絵日記の一覧に同じように適用する。
- **FR-016**: System MUST 既存の絵日記を、保存内容を変えずに新しいページの見た目で表示する。データの移行は行わない。
- **FR-017**: System MUST 幅360px以上の画面で、ページが画面の幅に収まり、横スクロールなしで記入と閲覧ができるようにする。
- **FR-018**: System MUST 記入画面のすべての操作(画像の選択、日付と天気の選択、文章の入力、保存)を、キーボードだけでも行えるようにし、各欄に読み上げ用の名前を付ける。

### Key Entities

- **絵日記**: 001 で定義した日付、天気、文章、画像1枚を持つ。今回の変更で項目は増減しない。
- **絵日記のページ**: 絵日記1件を表示する1枚のカード。絵の枠、日付欄、天気欄、罫線の文章欄で構成する。保存はせず、表示の形式である。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 400文字の文章を入力した場合も含め、記入画面と表示画面のすべての行で、文字が罫線の上に乗り、罫線と文字の位置のずれが行の高さの1割以内である。
- **SC-002**: 幅360pxの画面で、記入画面と表示画面に横スクロールが発生しない。
- **SC-003**: Chrome、Safari、Firefox、Edge の最新版で、文章と日付欄が同じ手書き風の書体で表示される。
- **SC-004**: 書体の読み込みを含めて、絵日記の表示画面が、下り10Mbps、遅延40msの回線で2秒以内に読める状態になる(書体のキャッシュがない初回の表示で測る)。
- **SC-005**: 試用した利用者の8割以上が、新しい画面を「紙の絵日記帳に近い」と評価する。
- **SC-006**: 書体の取得を含め、絵日記の画面から外部のサービスへの通信が発生しない。

## Assumptions

- 保存する内容(画像、文章、日付、天気)、文字数の上限(400文字)、日付の制約、公開範囲、エクスポートとインポートの形式は 001 のまま変えない。
- 参考画像の日付欄の右隣の欄は空欄だが、利用者の要望により、この欄を天気の入力と表示に使う。
- 年は日付欄に入れず、ページの外の見出しなどに表示する(参考画像の日付欄は月、日、曜日のみ)。
- ページの地の色は、参考画像の薄い灰色の紙を基本とし、ダークモードでも明るい紙の色を保つ。
- 手書き風の書体は、商用利用と再配布が許されたライセンスのものを使う。
- 縦書きの表示は今回すべてやめ、縦書きと横書きを利用者が切り替える機能は作らない。
- カレンダー、プロフィール、フォローなど、絵日記のページ以外の画面の見た目は今回の対象外とする。

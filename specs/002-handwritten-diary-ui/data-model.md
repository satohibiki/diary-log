# Data Model: 手書きの絵日記帳風 UI

## 保存するデータ

変更しない。絵日記(日付、天気、文章、画像1枚)の定義、制約、暗号化、エクスポートの形式は、[001 の data-model.md](../001-picture-diary-service/data-model.md) のとおり。

- **文章**: 1〜400文字(書記素で数える)。改行を含められる。
- **天気**: `sunny` | `cloudy` | `rainy` | `snowy`(表示名: 晴れ、くもり、雨、雪)。
- **日付**: `YYYY-MM-DD`。未来の日付は不可で、1利用者につき1日付1件。

## 表示用のモデル(保存しない)

### DiaryPage(絵日記のページ)

記入画面と表示画面で共通の、1枚のページの構成。

| 区画 | 内容 | 記入画面 | 表示画面 |
|---|---|---|---|
| 絵の枠 | 画像(縦横比 4:3 の枠に収める) | 選んだ画像のプレビュー、または空の枠。画像の選択欄 | 保存された画像 |
| 日付欄 | `formatDiaryDay(date)` の文字列(例: `11月 8日(日)`) | 日付の入力欄(ラベル「日付」)を重ねる | 文字列のみ |
| 天気欄 | 見出し「天気」と天気 | 4つのラジオボタン(晴れ、くもり、雨、雪) | 選ばれた天気の名前とアイコン |
| 文章欄 | 横書きの文章と点線の罫線 | 文章の入力欄(ラベル「文章」)と残りの文字数 | 文章(文字としてのみ表示) |

ページの外には、年(例: `2026年`)と、表示画面では書いた人のニックネームを置く。

### 派生する値

- **`formatDiaryDay(date: string): string`**: `YYYY-MM-DD` を `M月 D日(曜)` に変換する。
  - 月と日は0で埋めない。
  - 曜日は、既存の `formatJapaneseDate` と同じ計算を使う。
- **`ruledHeight(contentHeight: number, gap: number): number`**: 文章欄の高さを求める。
  - 結果は `max(8 × gap, ceil(contentHeight / gap) × gap)`。
  - 最小8行で、内容に合わせて罫線1行単位で増える。
  - `gap` が0以下のときは、エラーとして扱う(憲章 VIII)。

# Quickstart: ID とパスワードでのログインを確かめる

**Feature**: [spec.md](./spec.md) | **Date**: 2026-11-22

## 前提

- 001 の quickstart のとおり、開発用の DB(PostgreSQL)と Mailpit(http://localhost:8025)を起動できること。
- API は [contracts/auth-api.md](./contracts/auth-api.md)、データは [data-model.md](./data-model.md) を参照。

## 準備

```bash
npm run db:migrate   # users の列、trusted_devices、列挙型の値を追加する
```

## 自動テスト

```bash
npm run verify                # 型検査、lint、単体と統合のテスト、npm audit、secretlint
npx playwright test           # E2E(パスワードの登録とログインは全ブラウザ、パスキーは Chromium のみ)
```

E2E を手元で実行する場合は、開発サーバーを `APP_ORIGIN=https://localhost:5173 RP_ID=localhost npm run dev` で起動しておく(`.env` が LAN 用のホストの場合)。

## 手で確かめる手順

| # | 操作 | 期待する結果 | 対応 |
|---|---|---|---|
| 1 | パスキーを無効にしたブラウザ(または Firefox)で「アカウントを作成」。ID、メール、Mailpit の OTP、パスワード(12文字以上)を入力 | アカウントが作られ、ログイン状態になる。パスキーは求められない | US1-1、FR-001 |
| 2 | パスワードに `password1234`、ID を含むもの、11文字のものを入力 | それぞれ登録されず、理由が表示される | US1-5、FR-003 |
| 3 | ログアウトしてログイン画面を開く | ID とパスワードの欄が最初に出て、「パスキーでログイン」は別のボタン(非対応のブラウザでは無効と表示) | US1-2、US1-6 |
| 4 | 同じブラウザで ID とパスワードでログイン | OTP なしでログインできる(登録した端末は確認済み) | US1-9 |
| 5 | 別のブラウザ(またはシークレットウィンドウ)で同じ ID とパスワードを入力 | OTP の入力を求められる。Mailpit の OTP を入力するとログインでき、「新しい端末からログインしました」のメールが届く | US1-7、FR-015 |
| 6 | 存在しない ID と、存在する ID の誤ったパスワードでログイン | 同じエラーメッセージ | US1-4、FR-005 |
| 7 | セキュリティ設定でパスワードを変更 | ほかの端末がログアウトされ、通知メールが届く。次回のログインでは、この端末でも OTP を求められる | US3-1、FR-010、FR-015a |
| 8 | 対応ブラウザでパスワードで本人確認をしてパスキーを追加し、ログアウト後に「パスキーでログイン」 | パスワードと OTP なしでログインできる | US2-1、US2-2 |
| 9 | パスキーを1つだけ持つ状態で、そのパスキーを削除 | パスワードを持つため削除できる | US2-4、FR-011 |
| 10 | 「パスキーを使えない場合はこちら」から ID と OTP で復旧し、新しいパスワードを設定 | ログインでき、ほかの端末はログアウトされ、復旧の通知が届く | US3-3、FR-009 |

## 既存の利用者(パスキーだけ)を確かめる

1. main のコードで、パスキーでアカウントを作る(または E2E の `seedUser` で作る)。
2. このブランチに切り替えてマイグレーションを実行する。
3. 「パスキーでログイン」でログインできる(SC-003)。パスワードは求められない(FR-013)。
4. セキュリティ設定で、パスキーで本人確認をしてからパスワードを設定する。以後、パスワードでもログインでき、通知が届く(US3-2)。
5. この状態ではパスワードを持たないため、パスワードの設定の前は最後のパスキーを削除できない(FR-011)。

## ログに残らないことを確かめる

`npm run dev` の出力と、開発用 DB の `users.password_hash` を見て、入力したパスワードの文字列がどこにも現れないことを確かめる(SC-005)。自動では `apps/server/tests/integration/log-safety.test.ts` で確かめる。

# Feature Specification: ID とパスワードでのログイン(パスキーも利用可)

**Feature Branch**: `004-id-password-login`

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "パスキー認証のみであるとパスキーが利用できない端末で利用ができなくなってしまうため、IDとパスワードでのログインをデフォルトとしてパスキーでのログインも可能であるアプリケーションにしてください"

## 概要

001-picture-diary-service では、漏えいのリスクを抑えるため、ログインを ID とパスキーだけにし、パスワードを一切扱わないと定めた(001 FR-002、ADR-0003)。しかしパスキーに対応していない端末やブラウザでは、ログインも利用もできない。

この仕様では、ID とパスワードでのログインを標準の方法とし、パスキーでのログインも引き続き選べるようにする。001 の FR-001、FR-002、FR-004、FR-005、FR-005b、FR-005e と、パスキー非対応の環境の扱い(001 の Edge Cases)を置き換える。

パスワードを扱うことで生じる漏えいと推測のリスクは、パスワードの条件、復元できない形での保存、試行の制限、初めて使う端末での追加の確認、変更時の通知で抑える。

## Clarifications

### Session 2026-11-22

- Q: パスワードでのログインに、追加の確認を求めるか? → A: 初めて使う端末でだけ、登録済みのメールアドレスへ送るワンタイムパスワードも求める(確認済みの端末ではパスワードだけでログインできる)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ID とパスワードで登録してログインする (Priority: P1)

利用者は、ID、復旧用のメールアドレス、パスワードでアカウントを作成し、パスキーに対応していない端末でも、ID とパスワードでログインして絵日記を使う。

**Why this priority**: パスキーに対応していない端末で使えないことが、この変更の理由である。登録とログインができなければ、ほかのどの機能も使えない。

**Independent Test**: パスキーに対応していないブラウザで、新しい ID でアカウントを作成し、ログアウト後に ID とパスワードで再びログインできることを確認する。

**Acceptance Scenarios**:

1. **Given** アカウントを持たない利用者, **When** 未使用の ID とメールアドレスを入力し、メールに届いたワンタイムパスワードで確認して、条件を満たすパスワードを2回入力する, **Then** アカウントが作成され、ログイン状態になる(パスキーの登録は求めない)
2. **Given** 登録済みの利用者, **When** ログイン画面を開く, **Then** ID とパスワードの入力欄が最初から表示され、パスキーでのログインは別のボタンとして選べる
3. **Given** 確認済みの端末を使う登録済みの利用者, **When** ID と正しいパスワードを入力する, **Then** ログインできる
4. **Given** 登録済みの利用者, **When** ID またはパスワードを誤って入力する, **Then** ログインは失敗し、ID とパスワードのどちらが違うかは分からないメッセージと、復旧の手順への導線が表示される
5. **Given** 条件を満たさないパスワード(短すぎる、よく使われるもの、ID と同じなど), **When** 登録しようとする, **Then** 登録されず、満たしていない条件が表示される
6. **Given** パスキーに対応していない端末, **When** ログイン画面を開く, **Then** ID とパスワードでログインでき、パスキーのボタンは非対応である旨とともに無効になる
7. **Given** 初めて使う端末の利用者, **When** ID と正しいパスワードを入力する, **Then** 登録済みのメールアドレスへワンタイムパスワードが送られ、その入力を求められる。正しく入力するとログインでき、その端末は確認済みになり、新しい端末からのログインがメールで通知される
8. **Given** 初めて使う端末で、パスワードは正しいがワンタイムパスワードを入力できない第三者, **When** ログインを試みる, **Then** ログインできず、絵日記にはアクセスできない
9. **Given** アカウントを作成した端末, **When** その端末で後日 ID とパスワードでログインする, **Then** 登録時にメールアドレスを確認済みのため、ワンタイムパスワードを求めない

---

### User Story 2 - パスキーでもログインできる (Priority: P2)

利用者は、パスキーを登録しておけば、対応している端末ではパスワードを入力せずにパスキーでログインできる。

**Why this priority**: パスキーは、パスワードより安全で手早いログインの方法である。既にパスキーで登録した利用者が、これまでどおりログインできる必要がある。

**Independent Test**: パスワードでログインしてセキュリティ設定からパスキーを登録し、ログアウト後にパスキーでログインできることを確認する。

**Acceptance Scenarios**:

1. **Given** パスワードでログイン中の利用者, **When** セキュリティ設定でパスキーを追加する, **Then** パスキーが登録され、登録済みのメールアドレスへ通知される
2. **Given** パスキーを登録済みの利用者, **When** ログイン画面で「パスキーでログイン」を選んで認証する, **Then** パスワードを入力せずにログインできる
3. **Given** この変更の前にパスキーだけで登録した利用者, **When** ログイン画面で「パスキーでログイン」を選ぶ, **Then** これまでどおりログインできる
4. **Given** パスワードとパスキーの両方を持つ利用者, **When** パスキーを削除する, **Then** 削除でき、パスワードでのログインは続けて使える

---

### User Story 3 - パスワードを設定、変更、再設定する (Priority: P2)

利用者は、パスワードを変更できる。パスキーだけで登録した既存の利用者は、パスワードを追加できる。パスワードを忘れた利用者は、メールのワンタイムパスワードで新しいパスワードを設定できる。

**Why this priority**: パスワードを標準の方法にする以上、変更と再設定ができないと、忘れた利用者がアカウントを失う。既存の利用者がパスキー非対応の端末を使うには、パスワードの追加が必要である。

**Independent Test**: パスワードを変更して新しいパスワードでログインできること、ワンタイムパスワードで再設定できること、パスキーだけの利用者がパスワードを追加できることを確認する。

**Acceptance Scenarios**:

1. **Given** パスワードを持つログイン中の利用者, **When** 現在のパスワードと、条件を満たす新しいパスワードを入力する, **Then** パスワードが変わり、ほかの端末のログイン状態が終了し、登録済みのメールアドレスへ通知される
2. **Given** パスキーだけを持つログイン中の利用者, **When** パスキーで本人確認をしてからパスワードを設定する, **Then** 以後 ID とパスワードでもログインでき、メールで通知される
3. **Given** パスワードを忘れた利用者, **When** ID を入力し、登録済みのメールアドレスに届いたワンタイムパスワードを入力する, **Then** 新しいパスワードの設定(またはパスキーの登録)を求められ、設定が完了するとログインでき、ほかの端末のログイン状態は終了する
4. **Given** 誤った現在のパスワード, **When** パスワードを変更しようとする, **Then** 変更されない

---

### Edge Cases

- ID の存在の有無は、ログインの失敗の応答、応答までの時間、復旧の応答のいずれからも分からないようにする。
- パスワードでのログインの失敗が続く場合は、001 FR-008 のとおり試行を制限する。本人がログインできなくなるような、ID 単位での長時間の締め出しは行わない(第三者による妨害を防ぐため)。
- ログインの方法(パスワードかパスキー)を最低1つは残す。パスワードを持たない利用者は、最後のパスキーを削除できない。パスワードの削除の機能は設けない。
- ワンタイムパスワードによる復旧では、新しいパスワードの設定か新しいパスキーの登録だけを許可し、絵日記へのアクセスは設定の完了後に限る(001 FR-005b を置き換え)。
- パスワードは画面の入力欄で伏せ字で表示し、利用者が表示に切り替えられるようにする。パスワード管理ツールでの自動入力と生成を妨げない。
- パスワードの貼り付けを禁止しない。
- パスキーでのログインに失敗した場合も、パスワードでのログインに切り替えられる。
- パスキーでのログインには、初めて使う端末でもワンタイムパスワードを求めない(パスキー自体が端末と本人の確認を含むため)。
- 端末の確認済みの状態は、その端末のブラウザに保持する。ブラウザのデータを消した場合や、別のブラウザを使う場合は、初めて使う端末として扱う。
- 確認済みの状態は、最後にその端末でログインしてから90日で失効する。ログアウトしても失効しない。
- パスワードの変更と再設定、復旧の完了、退会の時は、すべての端末の確認済みの状態を失効させる。
- 初めて使う端末でのワンタイムパスワードの有効期限、試行の回数、同時に有効な件数、再送は、001 FR-005a のとおりとする。ワンタイムパスワードの入力を待つ間は、絵日記にアクセスできない。
- メールアドレスを使えなくなった利用者は、パスキーか確認済みの端末でログインし、FR-017 のとおりメールアドレスを変更する。どれも使えない場合の復旧は、この仕様の範囲外とする(001 と同じく、メールアドレスが復旧の唯一の手段である)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Users MUST be able to 一意の ID、確認済みのメールアドレス、パスワードでアカウントを作成できる。登録時にパスキーを求めてはならない(001 FR-001 を置き換え)。
- **FR-002**: System MUST ログイン画面の標準の方法として ID とパスワードの入力欄を表示し、パスキーでのログインを別の操作として提供する(001 FR-002 を置き換え)。
- **FR-003**: System MUST パスワードに次の条件を課す。
  - 12文字以上、64文字以上まで受け付ける(上限を64文字未満にしない)。
  - 英字、数字、記号などの組み合わせは強制しない。空白と日本語を含むすべての文字を受け付ける。
  - よく使われるパスワード、および ID と同じか ID を含むパスワードを拒否する。
  - 定期的な変更は求めない。
- **FR-004**: System MUST パスワードを復元できない形でのみ保存し、ログ、エラーメッセージ、通知、エクスポートのいずれにも含めてはならない(001 FR-039 にパスワードを加える)。
- **FR-005**: System MUST ログインの失敗時に、ID とパスワードのどちらが誤っていたかを示してはならない。ID が存在しない場合と、パスワードが誤っている場合とで、応答の内容と時間を区別できないようにする。
- **FR-006**: System MUST パスワードでのログインの試行を、001 FR-008 のログインの制限に含める。
- **FR-007**: Users MUST be able to 現在のパスワードを入力したうえで、パスワードを変更できる。
- **FR-008**: Users MUST be able to パスキーだけを持つ場合に、パスキーで本人確認をしたうえで、パスワードを設定できる。
- **FR-009**: Users MUST be able to パスワードとパスキーのどちらも使えなくなった場合に、ID と、登録済みのメールアドレスへ送信されるワンタイムパスワードで、新しいパスワードを設定するか新しいパスキーを登録してアカウントを復旧できる(001 FR-005、FR-005b を置き換え)。ワンタイムパスワードの条件は 001 FR-005a のとおりとする。
- **FR-010**: System MUST パスワードの設定、変更、再設定の完了時に、ほかのすべての端末のログイン状態を終了させ、登録済みのメールアドレスへ通知する。通知にパスワードを含めてはならない。
- **FR-011**: Users MUST be able to セキュリティ設定で、パスキーを追加、削除できる。パスワードを持つ利用者は、最後のパスキーも削除できる。パスワードを持たない利用者は、最後のパスキーを削除できない(001 FR-004 を置き換え)。
- **FR-012**: System MUST パスキーに対応していない環境では、パスキーでのログインのボタンを、非対応である旨とともに無効にし、ID とパスワードでのログインを使えるようにする(001 の Edge Cases「パスキーに対応していない環境」を置き換え)。
- **FR-013**: System MUST 既存のパスキーだけの利用者を、この変更の後も変えずにパスキーでログインできるようにし、パスワードの設定を強制してはならない。
- **FR-014**: System MUST パスワードの入力欄で、伏せ字と表示の切り替え、パスワード管理ツールによる自動入力と生成、および貼り付けを妨げない。
- **FR-015**: System MUST 初めて使う端末で ID とパスワードによるログインに成功した場合、ログインを完了する前に、登録済みのメールアドレスへ送信したワンタイムパスワードの入力を求める。正しく入力した端末を確認済みとし、以後その端末では90日間(最後のログインから数える)パスワードだけでログインできるようにする。確認の完了時に、新しい端末からのログインを登録済みのメールアドレスへ通知する。アカウントを作成した端末は確認済みとする。
- **FR-015a**: System MUST パスワードの変更と再設定、アカウントの復旧の完了、および退会の時に、そのアカウントのすべての端末の確認済みの状態を失効させる。
- **FR-016**: Users MUST be able to セキュリティ設定で、パスワードの有無と、登録済みのパスキーの一覧を確認できる。
- **FR-017**: Users MUST be able to パスキー、または確認済みの端末での現在のパスワードで本人確認をしたうえで、確認済みの新しいメールアドレスへ変更できる(001 FR-005e を置き換え)。変更の完了を、変更前と変更後の両方のメールアドレスへ通知する。

### Key Entities

- **ユーザー**: 001 のとおり。加えて、パスワードを持つかどうかを持つ。
- **パスワード**: ユーザーのログインに使う秘密の値。1人のユーザーにつき最大1つ。復元できない形でのみ保存する。設定または変更した日時を持つ。
- **パスキー**: 001 のとおり。ログインの方法の1つで、1人のユーザーが複数持てる。パスワードを持つユーザーは、パスキーを持たなくてもよい。
- **ワンタイムパスワード**: 001 のとおり。メールアドレスの確認、アカウントの復旧(新しいパスワードの設定またはパスキーの登録)、および初めて使う端末でのパスワードによるログインの確認に使う。
- **確認済みの端末**: ワンタイムパスワードで確認を済ませた、ユーザーとブラウザの組。最後にログインした日時を持ち、90日で失効する。端末を特定できる情報(機種名、IP アドレスなど)は保持しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: パスキーに対応していない主要なブラウザ(パスキーを無効にした Chrome、Edge、Firefox、Safari の最新版)で、初めての利用者が3分以内にアカウントを作成し、最初の絵日記を保存できる。
- **SC-002**: 登録済みの利用者の95%が、ID とパスワードで30秒以内にログインできる(001 SC-002 と同じ水準)。
- **SC-003**: この変更の前にパスキーで登録した利用者の100%が、変更の後もパスキーでログインできる。
- **SC-004**: ID が存在しない場合と、パスワードが誤っている場合のログインの失敗の応答が、内容で区別できず、応答の時間の差が利用者や第三者に判別できない程度に収まる。
- **SC-005**: パスワードの値が、保存されたデータ、ログ、エラーメッセージ、メール、エクスポートのどれからも読み取れない。
- **SC-006**: パスワードを忘れた利用者が、メールのワンタイムパスワードで5分以内に新しいパスワードを設定してログインできる。
- **SC-007**: 正しいパスワードを知っていても、登録済みのメールアドレスのワンタイムパスワードを入力できない第三者は、初めて使う端末からログインできない(確認のテストで成功が0件)。
- **SC-008**: 初めて使う端末でのパスワードによるログインを、利用者の90%が、メールの受信を含めて2分以内に完了できる。

## Assumptions

- パスワードは12文字以上とする。単独の認証要素としての強さと、紙の絵日記の延長として気軽に使えることの釣り合いをとる。上限は64文字以上とし、パスフレーズを使えるようにする。
- 「よく使われるパスワード」の判定は、サービス内に持つ一覧で行う。パスワードやその一部を外部のサービスへ送らない(憲章 III)。
- 試行の制限は、001 FR-008 と ADR-0003 の実装結果の値(IP ごと、IP と ID の組ごと)をパスワードでのログインにも使う。ID 単独での締め出しはしない。
- 新しいアカウントでは、登録の完了後にパスキーの追加を案内してよいが、必須にしない。
- 既存の利用者のデータ(絵日記、パスキー、メールアドレス)は変えない。パスワードは、利用者が設定するまで持たない。
- 退会時には、パスワードもほかのアカウントの情報と同じく削除する(001 FR-007)。
- この変更は、001 のパスワードを扱わない方針(FR-002)と ADR-0003 の前提を覆すため、計画の段階で新しい ADR を記録する。
- メールアドレスの確認と復旧のワンタイムパスワードの仕組み(有効期限、回数、同時に有効な件数)は、001 のまま変えない。

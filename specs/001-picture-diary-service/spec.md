# Feature Specification: 絵日記公開サービス

**Feature Branch**: `001-picture-diary-service`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "概要: 絵日記を作成、公開できるサービス。絵日記のフォーマット: 画像1枚＋文章、日付と天気を入れる、ユーザーは絵日記のような縦書きのUIで記入。検索機能: カレンダー形式で過去の絵日記を遡って探すことができる。共有機能: フォロー、フォロワー形式でフォローしているユーザーの日記が見れる。プロフィール: プロフィールはニックネームのみとして個人情報を入れないようにする、プロフィール画像を登録できるようにしたい、プロフィール画面でユーザーは自分の日記を公開するかどうか選択できる。ログイン: IDとパスキーでのログイン、パスワード入力を避けることで漏洩リスクを最小限にする"

## Clarifications

### Session 2026-11-07

- Q: 絵日記の本文と画像は、どこに保存しますか? → A: すべてサーバーに保存する
- Q: 公開中の絵日記は誰が閲覧でき、フォローに相手の承認は必要ですか? → A: ログイン中の承認済みフォロワーのみ閲覧でき、フォローは承認制にする
- Q: すべてのパスキーを使えなくなった利用者のアカウントは、どのように復旧しますか? → A: メールアドレスの登録を必須とし、登録先へワンタイムパスワードを送信して復旧する。個人情報を持たない方針はこの範囲で変更する
- Q: サーバーに保存する絵日記の内容を、運営者も読めない形にしますか? → A: サービスが管理する鍵で保存時に暗号化する。運営者も読めない方式は採用しない
- Q: インターネットに接続していないとき、利用者はどこまで使えるようにしますか? → A: 利用にはオンライン接続を必須とし、記入中の内容だけ端末に一時保持して、接続の回復後に利用者が保存する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - パスキーで登録してログインする (Priority: P1)

利用者は、ID、復旧用のメールアドレス、パスキーを登録してアカウントを作成し、パスワードを使わずに ID とパスキーでログインする。パスキーを使えなくなった場合は、メールアドレスへ届くワンタイムパスワードで復旧する。

**Why this priority**: すべての機能の入口であり、パスワードを持たないことが漏えいリスクを抑えるという本サービスの前提であるため。

**Independent Test**: 新しい ID でアカウントを作成し、ログアウト後にパスキーで再度ログインできること、およびワンタイムパスワードで新しいパスキーを登録できることを確認する。

**Acceptance Scenarios**:

1. **Given** アカウントを持たない利用者, **When** 未使用の ID とメールアドレスを入力し、メールに届いたワンタイムパスワードで確認してパスキーを登録する, **Then** アカウントが作成され、ログイン状態になる
2. **Given** 登録済みの利用者, **When** ID を入力してパスキーで認証する, **Then** ログインできる
3. **Given** 既に使われている ID, **When** 別の利用者がその ID で登録しようとする, **Then** 登録は拒否され、別の ID の入力を求められる
4. **Given** パスキーの認証に失敗した利用者, **When** ログインを試みる, **Then** ログインは失敗として通知され、復旧の手順への導線のみが提示される
5. **Given** ログイン中の利用者, **When** ログアウトする, **Then** ログイン状態が終了し、再度の認証なしでは自分の絵日記を閲覧できない
6. **Given** パスキーを使えなくなった利用者, **When** ID を入力し、登録済みのメールアドレスに届いたワンタイムパスワードを入力する, **Then** 新しいパスキーの登録を求められ、登録が完了するとログインできる
7. **Given** 誤ったまたは期限切れのワンタイムパスワード, **When** 復旧を試みる, **Then** 復旧は拒否され、絵日記にはアクセスできない

---

### User Story 2 - 縦書きで絵日記を書く (Priority: P1)

利用者は、紙の絵日記のように、画像1枚と縦書きの文章に日付と天気を添えて、その日の絵日記を記録する。編集や削除もできる。

**Why this priority**: サービスの中心となる価値であり、これだけでも個人の日記として利用できるため。

**Independent Test**: ログイン後に画像、文章、日付、天気を入力して保存し、同じ内容が縦書きの絵日記として表示され、編集と削除もできることを確認する。

**Acceptance Scenarios**:

1. **Given** ログイン中の利用者, **When** 絵日記の作成を始める, **Then** 日付に当日が設定された状態で、縦書きの記入画面が表示される
2. **Given** 記入画面, **When** 画像、文章、日付、天気を入力して保存する, **Then** 絵日記が保存され、縦書きで表示される
3. **Given** 画像、文章、または天気が未入力の記入画面, **When** 保存しようとする, **Then** 保存されず、不足している項目が示される
4. **Given** 保存済みの絵日記, **When** 本人が内容を編集して保存する, **Then** 変更後の内容が表示される
5. **Given** 保存済みの絵日記, **When** 本人が削除を選び確認画面で確定する, **Then** 絵日記と画像が削除される
6. **Given** 記入中の利用者, **When** 保存に失敗する, **Then** 失敗が通知され、入力内容は失われない

---

### User Story 3 - カレンダーで過去の絵日記を探す (Priority: P2)

利用者は、カレンダーを月単位で移動し、過去の自分の絵日記を日付から探して読む。

**Why this priority**: 記録が蓄積されるほど価値が高まる機能だが、記録が存在して初めて意味を持つため。

**Independent Test**: 複数の日付の絵日記を用意し、カレンダーで該当月へ移動して、日付を選ぶと絵日記が開くことを確認する。

**Acceptance Scenarios**:

1. **Given** 絵日記がある月, **When** カレンダーを表示する, **Then** 絵日記がある日付を見分けられる
2. **Given** カレンダー, **When** 前後の月へ移動する, **Then** その月の絵日記の有無が表示される
3. **Given** 絵日記がある日付, **When** その日付を選ぶ, **Then** その日の絵日記が表示される
4. **Given** 絵日記がない過去または当日の日付, **When** その日付を選ぶ, **Then** その日付で絵日記を作成できる

---

### User Story 4 - プロフィールと公開設定を管理する (Priority: P2)

利用者は、個人情報を含まないニックネームとプロフィール画像を設定し、自分の絵日記を公開するかどうかをプロフィール画面で選ぶ。

**Why this priority**: 共有を始める前に、利用者自身が公開範囲を管理できる必要があるため。

**Independent Test**: ニックネームと画像を設定し、公開設定を切り替えたときに、別のアカウントからの見え方が設定どおりに変わることを確認する。

**Acceptance Scenarios**:

1. **Given** ログイン中の利用者, **When** ニックネームを保存する, **Then** プロフィールと公開中の絵日記にそのニックネームが表示される
2. **Given** ログイン中の利用者, **When** プロフィール画像を登録または削除する, **Then** プロフィール表示に反映される
3. **Given** 登録直後の利用者, **When** 公開設定を確認する, **Then** 非公開に設定されている
4. **Given** 非公開の利用者, **When** 公開に切り替える, **Then** 過去の絵日記も公開対象になることが確認画面で示され、確定後に公開される
5. **Given** 公開中の利用者, **When** 非公開に切り替える, **Then** 本人以外は、そのすべての絵日記を閲覧できなくなる

---

### User Story 5 - フォローしているユーザーの絵日記を読む (Priority: P3)

利用者は、他のユーザーにフォローを申請し、承認されるとその絵日記を読める。自分宛ての申請の承認や拒否、フォロワーの確認、望まない相手の削除もできる。

**Why this priority**: 共有は本サービスの特徴だが、個人の記録と公開設定が先に成立している必要があるため。

**Independent Test**: 2つのアカウントを用意し、一方がもう一方を ID で検索してフォローを申請し、相手の承認後に、公開中の絵日記が一覧に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ログイン中の利用者, **When** 他のユーザーの ID を検索してフォローを申請する, **Then** 相手の承認待ちになり、承認されるまで絵日記は閲覧できない
2. **Given** フォローの申請を受けた利用者, **When** 申請を承認する, **Then** 申請者がフォロワーになる
3. **Given** フォローの申請を受けた利用者, **When** 申請を拒否する, **Then** 申請者はフォロワーにならず、絵日記を閲覧できない
4. **Given** 承認済みのフォロー中のユーザーがいる利用者, **When** 一覧画面を開く, **Then** 閲覧を許可された絵日記が新しい日付順に表示される
5. **Given** フォロー中の利用者, **When** フォローを解除する, **Then** 相手の絵日記は一覧に表示されなくなる
6. **Given** フォロワーがいる利用者, **When** フォロワーを削除またはブロックする, **Then** 相手は自分の絵日記を一覧で閲覧できなくなる
7. **Given** ブロックされた利用者, **When** ブロックした相手にフォローを申請しようとする, **Then** 申請できない

---

### Edge Cases

- 同じ日付の絵日記が既にある場合、新規作成せず、既存の絵日記の編集へ案内する。
- 未来の日付は選択できない。
- 対応していない形式、上限を超えるサイズ、または画像として読み取れないファイルは拒否し、理由を表示する。
- 文章の文字数が上限に達した場合は、残り文字数を示し、上限を超える保存を拒否する。
- 文章や画像に含まれる位置情報などの埋め込み情報は、他者に見える状態で保持しない。
- 文章やニックネームにマークアップやスクリプトが含まれていても、文字としてのみ表示する。
- 狭い画面でも、縦書きの記入欄が画面からはみ出さず、横スクロールなしで利用できる。
- パスキーに対応していない環境では、非対応であることを表示する。ワンタイムパスワードを通常のログイン手段として使うことはできない。
- 復旧の要求に対する応答からは、ID の存在の有無やメールアドレスが分からない。
- メールが届かない場合は再送でき、再送すると以前のワンタイムパスワードは無効になる。
- 承認待ちの申請は、申請者が取り消せる。ブロックすると、相手からの承認待ちの申請は取り消される。
- フォロー中のユーザーが非公開に切り替えた場合、フォロー関係は維持し、絵日記だけを閲覧不可にする。
- 閲覧権限のない絵日記の URL に直接アクセスした場合、内容も存在の有無も明かさない。
- 退会したユーザーの絵日記、プロフィール、およびフォロー関係は、他の利用者の画面に表示されない。
- 接続が切れた状態で保存しようとした場合、保存は失敗として通知し、接続の回復後に利用者が再度保存できる。自動での再送は行わない。
- 通信の失敗やサーバーのエラー時は、古い内容や空の画面で隠さず、失敗として表示する。

## Requirements *(mandatory)*

### Functional Requirements

**認証とアカウント**

- **FR-001**: Users MUST be able to 一意の ID とパスキーでアカウントを作成できる。
- **FR-002**: System MUST 通常のログインを ID とパスキーのみで提供し、パスワードの設定、入力、保存を行ってはならない。
- **FR-003**: System MUST 登録時に、確認済みのメールアドレスを復旧用として必須とする。電話番号、氏名、生年月日、住所を要求してはならない。
- **FR-004**: Users MUST be able to 1つのアカウントに複数のパスキーを登録し、不要なものを削除できる。ただし最後の1つは削除できない。
- **FR-005**: Users MUST be able to パスキーをすべて利用できなくなった場合に、ID を指定し、登録済みのメールアドレスへ送信されるワンタイムパスワードでアカウントを復旧できる。
- **FR-005a**: System MUST ワンタイムパスワードを推測困難な値とし、有効期限を10分、使用を1回限り、入力の試行を5回までとする。
- **FR-005b**: System MUST ワンタイムパスワードによる認証では、新しいパスキーの登録のみを許可する。絵日記へのアクセスは登録完了後に限る。
- **FR-005c**: System MUST 復旧の完了とパスキーの追加を、登録済みのメールアドレスへ通知する。
- **FR-005d**: System MUST メールアドレスを本人以外に表示してはならない。
- **FR-005e**: Users MUST be able to パスキーで認証したうえで、確認済みの新しいメールアドレスへ変更できる。
- **FR-006**: Users MUST be able to ログアウトできる。
- **FR-007**: Users MUST be able to 確認のうえ退会でき、System MUST 退会時に絵日記、画像、プロフィール、メールアドレス、およびフォロー関係を削除する。
- **FR-008**: System MUST ログインと復旧の試行の連続失敗、ID の大量照会、およびワンタイムパスワードの大量送信を制限する。

**絵日記**

- **FR-009**: Users MUST be able to 画像1枚、文章、日付、天気からなる絵日記を作成できる。4項目はすべて必須とする。
- **FR-010**: System MUST 記入画面と閲覧画面の文章を、右から左へ行が進む縦書きで、紙の絵日記のように表示する。
- **FR-011**: System MUST 1人の利用者につき1日付1件の絵日記のみを許可する。
- **FR-012**: System MUST 日付の初期値を当日とし、過去の日付を選択可能にし、未来の日付を拒否する。
- **FR-013**: Users MUST be able to 天気を「晴れ」「くもり」「雨」「雪」から1つ選択できる。
- **FR-014**: System MUST 文章を1文字以上400文字以内に制限する。
- **FR-015**: System MUST 絵日記の画像として JPEG、PNG、WebP の10MB以下のファイルのみを受け付け、内容が実際に画像であることを検証する。
- **FR-016**: Users MUST be able to 自分の絵日記を編集でき、確認のうえ削除できる。
- **FR-017**: System MUST 記入中の内容を、保存の失敗、接続の切断、およびタブの終了で失われないよう端末に一時保持し、保存の完了時とログアウト時に端末から消去する。
- **FR-018**: System MUST 保存の失敗を利用者に明確に通知する。
- **FR-019**: System MUST すべての絵日記の本文と画像をサーバーに保存し、ログインした本人が複数の端末から利用できるようにする。
- **FR-020**: Users MUST be able to 自分のすべての絵日記を公開仕様の形式でエクスポートでき、同じ形式からインポートできる。

**検索**

- **FR-021**: Users MUST be able to 自分の絵日記を月単位のカレンダーで閲覧し、前後の月へ移動できる。
- **FR-022**: System MUST カレンダー上で絵日記がある日付を識別できるように表示し、選択するとその絵日記を表示する。
- **FR-023**: Users MUST be able to カレンダーの絵日記がない過去または当日の日付から、その日付の絵日記を作成できる。

**プロフィールと公開設定**

- **FR-024**: System MUST プロフィールの入力項目をニックネーム(1〜20文字)とプロフィール画像のみとする。
- **FR-025**: Users MUST be able to プロフィール画像を登録、変更、削除できる。形式とサイズの制限は FR-015 と同じとし、未登録時は共通の画像を表示する。
- **FR-026**: Users MUST be able to プロフィール画面で、自分の絵日記全体を公開するか非公開にするかを選択できる。
- **FR-027**: System MUST 公開設定の初期値を非公開とする。
- **FR-028**: System MUST 非公開から公開へ切り替える際に、過去の絵日記も対象になることを示して確認を取る。
- **FR-029**: System MUST 公開中の絵日記を、本人とログイン中の承認済みフォロワーのみに表示する。未ログインの人と未承認の利用者には表示してはならない。

**フォローと閲覧**

- **FR-030**: Users MUST be able to 他のユーザーを ID の完全一致で検索し、ニックネームとプロフィール画像を確認して、フォローの申請、申請の取り消し、およびフォローの解除ができる。
- **FR-030a**: Users MUST be able to 自分宛てのフォロー申請を承認または拒否できる。承認されるまでフォロー関係は成立しない。
- **FR-031**: Users MUST be able to 自分のフォロー中、フォロワー、および承認待ちの申請の一覧を確認できる。
- **FR-032**: Users MUST be able to フォロワーを削除でき、他のユーザーをブロックできる。ブロックされたユーザーは、ブロックした相手にフォローを申請することも、その絵日記を閲覧することもできない。
- **FR-033**: System MUST 承認済みのフォローをしているユーザーの閲覧可能な絵日記を、日付の新しい順に一覧表示する。
- **FR-034**: Users MUST be able to 承認済みのフォローをしているユーザーのページで、そのユーザーのニックネーム、プロフィール画像、および閲覧可能な絵日記を閲覧できる。

**セキュリティとプライバシー**

- **FR-035**: System MUST すべての閲覧と変更で権限を確認し、非公開の絵日記を本人以外に、URL の直接指定を含めて一切提供してはならない。
- **FR-036**: System MUST 公開設定の変更や削除を、他の利用者の閲覧に直ちに反映する。
- **FR-037**: System MUST アップロードされた画像から、位置情報や撮影機器情報などの埋め込み情報を、保存前に取り除く。
- **FR-038**: System MUST 文章とニックネームを文字としてのみ扱い、スクリプトやマークアップとして解釈してはならない。
- **FR-039**: System MUST 絵日記の内容、画像、メールアドレス、ワンタイムパスワード、およびパスキーの情報をログやエラーメッセージに出力してはならない。
- **FR-040**: System MUST アナリティクス、広告、トラッキング、および外部へのエラー送信を組み込んではならない。外部へ送信するメールには、絵日記の内容を含めてはならない。
- **FR-041**: System MUST 通信を常に暗号化する。
- **FR-042**: System MUST エラーを既定値や空の結果で隠さず、失敗として表示する。
- **FR-043**: System MUST 絵日記の本文、画像、プロフィール画像、およびメールアドレスを、サービスが管理する鍵で暗号化して保存する。
- **FR-044**: System MUST 運営者による利用者データへのアクセスを、障害対応など必要な場合に限定し、すべてのアクセスを記録する。
- **FR-045**: System MUST インターネットに接続していない場合、接続が必要であることを表示し、保存済みの絵日記を端末に保持してはならない。

### Key Entities *(include if feature involves data)*

- **ユーザー**: サービスの利用者。ID、ニックネーム、プロフィール画像、公開設定、および復旧用のメールアドレスを持つ。公開されるプロフィールはニックネームとプロフィール画像のみとする。
- **ワンタイムパスワード**: メールアドレスの確認とアカウントの復旧に使う、1回限りの短期間有効な値。
- **パスキー**: ユーザーのログインに使う認証情報。1人のユーザーが複数持てる。
- **絵日記**: 1人のユーザーの1日分の記録。日付、天気、文章、絵日記画像1枚を持つ。
- **フォロー関係**: フォローするユーザーとされるユーザーの関係。状態は承認待ちまたは承認済みのいずれかを持つ。
- **ブロック**: ブロックしたユーザーと、ブロックされたユーザーの関係。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めての利用者の90%が、3分以内にアカウントを作成して最初の絵日記を保存できる。
- **SC-002**: 登録済みの利用者の95%が、30秒以内にログインできる。
- **SC-003**: 利用者が過去1年以内の任意の日付の絵日記を、10秒以内に開ける。
- **SC-004**: 権限のない利用者による非公開の絵日記の閲覧が、検証シナリオのすべてで0件である。
- **SC-005**: 非公開への切り替えから5秒以内に、本人以外がその絵日記を閲覧できなくなる。
- **SC-006**: サービスが保持する利用者情報に、パスワードが0件である。本人以外の画面に表示されるメールアドレスも0件である。
- **SC-007**: 他の利用者が取得できる画像に、位置情報が含まれるケースが0件である。
- **SC-008**: フォロー中の絵日記の一覧が、通常の利用時に95%のケースで2秒以内に表示される。
- **SC-009**: 幅360pxの画面で、すべての主要画面が横スクロールなしで利用できる。
- **SC-010**: 主要な操作のすべてを、キーボードのみで完了できる。

## Assumptions

- 主な利用者は、パスキーに対応した端末とブラウザを持つ個人である。
- 運営者は技術的には絵日記の内容を読める。利用者には、利用開始前にこのことを説明する。
- メールアドレスは登録時と復旧時の確認にのみ使い、宣伝などの目的には使わない。
- 復旧は ID で対象を特定するため、同じメールアドレスを複数のアカウントで使用できる。
- ワンタイムパスワードの送信には、メールの配信手段が必要である。
- 対象はモダンブラウザで利用する Web アプリである。ネイティブアプリは今回の範囲外とする。
- 公開設定は絵日記ごとではなく、アカウント全体で1つとする。
- 天気は利用者が選択し、外部の気象情報からの自動取得は行わない。
- 文章の上限は原稿用紙1枚分の400文字とする。
- 他のユーザーの絵日記はカレンダーではなく、一覧とユーザーページで閲覧する。
- ユーザーの検索は ID の完全一致のみとし、ニックネームやおすすめによる発見は範囲外とする。
- コメント、いいね、通知、および下書きの複数端末間での同期は範囲外とする。
- 画像は利用者が用意したものをアップロードし、アプリ内での描画機能は範囲外とする。
- 通報と運営による投稿管理は今回の範囲外とする。一般公開の前には別途検討が必要である。

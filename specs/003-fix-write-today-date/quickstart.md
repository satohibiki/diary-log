# Quickstart: 「書く」の日付の不具合修正を確かめる

**Feature**: [spec.md](./spec.md) | **Date**: 2026-11-22

## 前提

- 001 の quickstart のとおり、開発用の DB とサーバーを起動できること。
- 振る舞いの約束は [contracts/diary-editor-ui.md](./contracts/diary-editor-ui.md)、書きかけのキーは [data-model.md](./data-model.md) を参照。

## 自動テスト

```bash
npm test                                  # 単体テスト(apps/web/tests/draft-store.test.ts、diary-editor.test.tsx、dates.test.ts など)
npx playwright test e2e/diary.spec.ts     # 「書く」の日付、書きかけ、案内の E2E
npm run lint && npm run typecheck
```

期待する結果: すべて成功する。修正前のコードでは、追加した不具合の再現テストが失敗すること(TDD の確認)。

## 手で確かめる手順

開発サーバー(`npm run dev`)を起動し、ログインした状態で行う。

| # | 操作 | 期待する結果 | 対応 |
|---|---|---|---|
| 1 | 「書く」を開き、何も入力せずにカレンダーへ移る。ブラウザの開発者ツールで IndexedDB `diary-drafts` を見る | `<user>:new:` で始まるキーが増えていない | FR-004 |
| 2 | 「書く」で文章を少し書き、カレンダーで過去の日付(例: 15日)を選ぶ | 日付欄は選んだ日付で、文章欄は空。「書きかけの絵日記があります」に今日の日付のリンクが出る | FR-002、FR-003、FR-006 |
| 3 | 2 の画面のまま「書く」を押す | 日付欄が今日に戻り、手順2で書いた文章が戻る | FR-001、research §5 |
| 4 | 今日の画面で日付を 15日に変える(15日に書きかけがない状態で) | 確認は出ない。案内から今日のリンクが消える | FR-005 |
| 5 | 別の日付の書きかけがある状態で、日付をその日付に変える | 置き換えの確認が出る。キャンセルすると日付が元に戻る | contracts「日付の変更」 |
| 6 | 書きかけのある日付で保存する | 保存した日付の書きかけだけが消え、ほかの日付の案内は残る | FR-007 |

## 修正前の書きかけの移行を確かめる

1. 修正前のコード(main)で「書く」を開き、文章を入力して離れる(`<user>:new` が作られる)。
2. 修正後のコードに切り替え、「書く」を開く。
3. `<user>:new` が消え、`<user>:new:<手順1の日付>` に内容が移っている。手順1が今日でなければ、案内にその日付が出る。
4. 手順1で何も入力していなかった場合は、`<user>:new` が消え、新しいキーは作られない。

## 日付をまたぐ確認

単体テストと E2E では、時計を固定して確かめる(E2E は Playwright の `page.clock`)。手で確かめる場合は、端末の日付を変えて、11月8日に「書く」を開いて離れたあと、11月22日に「書く」を開き、日付欄が「11月 22日(日)」になることを見る。

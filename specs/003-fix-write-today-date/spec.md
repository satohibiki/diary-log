# Feature Specification: 「書く」で開く絵日記の日付を今日にする(不具合修正)

**Feature Branch**: `003-fix-write-today-date`

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "「書く」ボタンをクリックしたときに開かれる絵日記の日付が今日の日付ではないバグが発生しているためspecを見直してください(スクリーンショット: 今日は2026-11-22だが、書く画面で「11月 8日(日)」と表示されている)"

## 概要

001-picture-diary-service の FR-012 は「日付の初期値を当日とする」と定めているが、2026-11-22 に「書く」を開くと、日付欄に「11月 8日(日)」が表示された。

原因は、001 の FR-017(記入中の内容の一時保持)と FR-012 の優先順位が仕様で決まっていなかったことにある。新しく書く絵日記の書きかけは、日付に関係なく1つだけ保持される。しかも何も入力していなくても、画面を開いただけで日付を含めて保持される。そのため、以前に開いた日の日付が、次に「書く」を開いたときにも残る。

この仕様では、書きかけを日付ごとに分けて保持し、「書く」では必ず今日の日付で開くように、001 の FR-012 と FR-017 を補う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 「書く」を押すと今日の絵日記が開く (Priority: P1)

利用者は、ナビゲーションの「書く」を押して、今日の絵日記を書き始める。以前に別の日の記入画面を開いたことがあっても、日付欄には今日の月、日、曜日が表示される。

**Why this priority**: 「書く」の主な用途は今日の絵日記を書くことである。別の日付で開くと、利用者が気づかずに別の日の絵日記として保存してしまう。

**Independent Test**: ある日に「書く」を開いて何も入力せずに離れ、端末の日付を進めてから再び「書く」を開き、日付欄が新しい日付になっていることを確認する。

**Acceptance Scenarios**:

1. **Given** 11月8日に「書く」を開いて、何も入力せずに離れた利用者, **When** 11月22日に「書く」を押す, **Then** 日付欄に「11月 22日(日)」が表示される
2. **Given** 11月8日に「書く」を開いて、文章を途中まで書いて離れた利用者, **When** 11月22日に「書く」を押す, **Then** 日付欄は11月22日で、文章欄は空である(11月8日の書きかけは11月22日の絵日記に入らない)
3. **Given** 今日の日付で文章を途中まで書いて離れた利用者, **When** 同じ日に再び「書く」を押す, **Then** 日付欄は今日で、書きかけの文章、天気、絵が戻る
4. **Given** 今日の絵日記を既に保存した利用者, **When** 「書く」を押す, **Then** 日付欄は今日である(1日1件の扱いは 001 のとおり、保存時に既存の絵日記の編集へ案内する)

---

### User Story 2 - カレンダーから選んだ日付で開く (Priority: P2)

利用者は、カレンダーで絵日記がない過去の日付を選び、その日付の絵日記を書く。ほかの日付の書きかけがあっても、選んだ日付で開く。

**Why this priority**: 001 の FR-023(カレンダーから過去の日付の絵日記を作成)が、同じ原因で別の日付になって開くおそれがある。

**Independent Test**: 今日の日付で文章を途中まで書いて離れ、カレンダーで過去の日付を選び、選んだ日付で空の記入画面が開くことを確認する。

**Acceptance Scenarios**:

1. **Given** 今日の書きかけがある利用者, **When** カレンダーで11月15日を選ぶ, **Then** 日付欄は「11月 15日(日)」で、今日の書きかけの内容は入っていない
2. **Given** 11月15日の書きかけがある利用者, **When** カレンダーで11月15日を選ぶ, **Then** 日付欄は11月15日で、その書きかけの内容が戻る

---

### User Story 3 - ほかの日付の書きかけに気づける (Priority: P3)

利用者は、今日ではない日付の書きかけが残っていることに、「書く」の画面で気づき、その書きかけを開ける。

**Why this priority**: 書きかけを日付ごとに分けると、今日以外の書きかけが「書く」から見えなくなり、利用者が書いた内容を見失うおそれがある。

**Independent Test**: 過去の日付の書きかけを残して「書く」を開き、その書きかけがあることの案内が表示され、案内からその日付の記入画面を開けることを確認する。

**Acceptance Scenarios**:

1. **Given** 11月8日の書きかけ(文章、天気、絵のいずれかが入力済み)がある利用者, **When** 11月22日に「書く」を開く, **Then** 「11月8日の書きかけがあります」という案内が表示され、案内から11月8日の記入画面を開ける
2. **Given** 何も入力していない書きかけしかない利用者, **When** 「書く」を開く, **Then** 書きかけの案内は表示されない

---

### Edge Cases

- 何も入力していない状態(文章、天気、絵のすべてが空)の記入画面は、書きかけとして保持しない。
- 記入画面で日付を変更して入力した場合、その書きかけは変更後の日付のものとして保持する。変更前の日付の書きかけには残さない。
- 記入画面を開いたまま日付が変わった(深夜0時を過ぎた)場合、日付欄は開いた時点の日付のままとし、勝手に変えない。保存の可否は 001 の未来日付の制約に従う。
- カレンダーなどから未来の日付や不正な日付が指定された場合は、今日の日付で開く。
- この修正より前に保持された書きかけ(日付の区別がないもの)は、その書きかけに記録された日付の書きかけとして扱う。内容が空なら破棄する。
- 絵日記の保存に成功したら、その日付の書きかけだけを消去する。ほかの日付の書きかけは残す。
- 今日の日付で絵日記が既に保存済みの場合も、「書く」の日付は今日とする(001 の1日1件の扱いを変えない)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST ナビゲーションの「書く」から開いた記入画面の日付を、利用者の端末の今日の日付にする。保持されている書きかけの日付で、この日付を置き換えてはならない(001 FR-012 の補足)。
- **FR-002**: System MUST カレンダーなどで日付を指定して記入画面を開いた場合、指定された日付で開く。指定された日付が不正または未来の場合は、今日の日付で開く。
- **FR-003**: System MUST 新しく書く絵日記の書きかけを日付ごとに分けて保持し、記入画面を開いたときは、その画面の日付の書きかけだけを戻す(001 FR-017 の補足)。
- **FR-004**: System MUST 文章、天気、絵のいずれも入力されていない状態を、書きかけとして保持しない。
- **FR-005**: System MUST 記入画面で日付を変更した場合、以後の入力内容を変更後の日付の書きかけとして保持する。
- **FR-006**: System MUST 「書く」の記入画面で、今日以外の日付の書きかけ(内容が空でないもの)がある場合、その日付を示す案内を表示し、案内からその日付の記入画面を開けるようにする。
- **FR-007**: System MUST 絵日記の保存に成功したとき、保存した日付の書きかけを消去する。ログアウト時はすべての書きかけを消去する(001 FR-017 のとおり)。
- **FR-008**: System MUST この修正より前に保持された日付の区別がない書きかけを、記録された日付の書きかけとして引き継ぎ、内容が空のものは破棄する。
- **FR-009**: System MUST 既存の絵日記の編集画面では、従来どおりその絵日記の日付で開き、日付を変更できない(001 のとおり)。

### Key Entities

- **書きかけ**: 保存前の入力内容を端末に一時保持したもの。利用者と日付の組ごとに最大1件を持ち、日付、文章、天気、絵を含む。編集中の既存の絵日記の書きかけは、従来どおり絵日記ごとに持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 書きかけの有無や過去に開いた日付に関係なく、「書く」を押したときの日付欄が、100%の確認ケースで今日の日付になる。
- **SC-002**: カレンダーで選んだ日付から開いた記入画面の日付が、100%の確認ケースで選んだ日付になる。
- **SC-003**: ある日付の書きかけの内容が、別の日付の記入画面に表示される件数が0件になる。
- **SC-004**: 今日以外の日付の書きかけがある利用者が、「書く」の画面から1回の操作でその書きかけを開ける。

## Assumptions

- 「今日」は、001 FR-012 のとおり利用者の端末の現地日付とする。サーバー側の未来日付の判定(UTC+14 基準)は変えない。
- 書きかけの保持場所は、001 と憲章 II のとおり利用者の端末のみとし、複数端末間で同期しない。
- 書きかけを日付ごとに保持する件数の上限は設けない。ただし空の書きかけは保持しないため、通常は少数に収まる。
- 案内(FR-006)に複数の日付の書きかけを示す場合は、新しい日付順に並べる。
- 記入画面の見た目(002 のページ構成)、保存する項目、1日1件の制約は変えない。

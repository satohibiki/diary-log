# Data Model: 「書く」で開く絵日記の日付を今日にする

**Feature**: [spec.md](./spec.md) | **Date**: 2026-11-22

サーバーに保存するデータ(絵日記、利用者など)は変えない。変えるのは、端末の IndexedDB に一時保持する書きかけのキーだけである。

## 書きかけ(Draft)

保存場所: IndexedDB のデータベース `diary-drafts`(バージョン 1 のまま)、オブジェクトストア `drafts`。

| 項目 | 型 | 説明 |
|---|---|---|
| date | `YYYY-MM-DD` | 絵日記の日付。新規の書きかけでは、キーの日付と同じ値になる |
| body | string | 文章 |
| weather | `'' \| Weather` | 天気。未選択は空文字 |
| image | `{ type, data: ArrayBuffer } \| null` | 絵。保存の形は変えない |

### キー

| 種類 | 修正前 | 修正後 |
|---|---|---|
| 新規の書きかけ | `<user>:new`(1人1件) | `<user>:new:<YYYY-MM-DD>`(1人1日付1件) |
| 編集の書きかけ | `<user>:<YYYY-MM-DD>` | 変えない |

利用者の新規の書きかけの一覧は、キーの範囲 `[<user>:new:, <user>:new:￿]` で読む。範囲の終わりの `￿` により、ほかの利用者のキーや、修正前のキー `<user>:new` は範囲に入らない。

### 規則

- **空**: `body.trim() === ''`、`weather === ''`、`image === null` のすべてを満たす書きかけ。新規の書きかけでは、空のものを保持しない。保持する代わりに、そのキーを消す(FR-004)。
- **日付の変更**: 記入画面で日付を A から B に変えたら、内容を `<user>:new:B` に保持し、`<user>:new:A` を消す(FR-005)。`<user>:new:B` に空でない書きかけがあれば、置き換える前に確認する。
- **消去**: 保存の成功時は、保存した日付のキーだけを消す。ログアウトと退会の時は、ストア全体を消す(変えない)。

### 状態の移り変わり(新規の書きかけ、ある日付について)

```text
なし ──(空でない入力)──▶ 保持 ──(入力をすべて消す)──▶ なし
                          │
                          ├──(保存に成功)──▶ なし
                          ├──(日付を変える)──▶ なし(変更後の日付へ移る)
                          └──(ログアウト、退会)──▶ なし
```

### 修正前の書きかけの移行(FR-008)

記入画面を開いたとき、`<user>:new` があれば、1つの readwrite トランザクションで次を行う。

1. 空なら消す。
2. 空でなければ、`<user>:new:<date>` が無い場合に限り、そこへ書き込む。
3. `<user>:new` を消す。

`date` が正しい形式でない場合は、移行せずにエラーとして利用者に示す(憲章 VIII)。修正前のコードは常に正しい日付を書き込んでいたため、通常は起きない。

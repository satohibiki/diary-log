# Contract: 新規の記入画面の日付と書きかけ

**Feature**: [../spec.md](../spec.md) | **Date**: 2026-11-22

サーバーの API は変えない。この文書は、新規の記入画面(`/diaries/new`)が利用者と他の画面に約束する振る舞いを定める。

## URL

| URL | 開く日付 |
|---|---|
| `/diaries/new`(ナビゲーションの「書く」) | 端末の今日の日付 |
| `/diaries/new?date=YYYY-MM-DD`(カレンダー、書きかけの案内) | 指定された日付。形式が正しくない、実在しない、または今日より後の場合は今日 |
| `/diaries/:date/edit` | 変えない(その絵日記の日付で開き、日付は変更できない) |

- 書きかけの日付で、開く日付を置き換えない。
- 新規の記入画面から別の新規の記入画面の URL へ移ったとき(例: `?date=2026-11-15` を開いた状態で「書く」を押す)は、移動先の URL の日付で開き直す。

## 書きかけの復元

- 開いた日付と同じ日付の新規の書きかけだけを、文章、天気、絵に戻す。
- ほかの日付の書きかけの内容は、画面に入れない。

## 書きかけの案内

- 表示する条件: 画面の日付以外の日付に、空でない新規の書きかけが1件以上ある。
- 表示する場所: 見出し「絵日記を書く」の下、ページ(カード)の上。
- 内容: 「書きかけの絵日記があります」という文と、日付のリンクの一覧(新しい日付順)。
  - リンクの文字は `formatJapaneseDate` の形式(例: 「2026年11月8日(日)」)。
  - リンク先は `/diaries/new?date=<date>`。
- 読み上げ: 案内は `aria-label="書きかけの絵日記"` を付けた `nav` 要素とする。キーボードでリンクを選べる。
- 空の書きかけしかない場合や、書きかけがない場合は、何も表示しない。

## 日付の変更

- 日付を変えると、以後の入力は変更後の日付の書きかけとして保持される。変更前の日付の書きかけは消える。
- 変更後の日付に空でない書きかけがある場合、確認ダイアログ「YYYY年M月D日(曜)の書きかけを、いま書いている内容で置き換えますか?」を出す。
  - OK: 置き換える。
  - キャンセル: 日付を変更前に戻し、どちらの書きかけも変えない。

## 保持しない状態

- 文章が空白のみ、天気が未選択、絵がない状態は保持しない。この状態になったら、その日付の書きかけを消す。

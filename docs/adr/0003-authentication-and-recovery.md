# ADR-0003: 認証と復旧

- **Status**: 提案中
- **Date**: 2026-11-07

## 背景

仕様は ID とパスキーによるログインを求め、復旧にはメールのワンタイムパスワードを使う。

## 決定

Discoverable Credential と User Verification を必須とするパスキーを使い、ログイン時の
`allowCredentials` は空にする。セッションは DB に保存し、`HttpOnly`、`Secure`、`SameSite=Strict` の
Cookie で管理する。復旧は10分有効の制限付きセッションで、新しいパスキーの登録のみを許可し、完了時に
他のセッションを失効させて通知する。

## 検討した代替案

- `allowCredentials` の指定: ID を列挙される。
- JWT: 失効の仕組みが別途必要になる。
- 復旧コード: 利用者の判断によりメール方式を採用した。

## 影響

メールの乗っ取りが最大のリスクとして残る。Discoverable Credential に対応しない認証器は使えない。

## 実装結果(2026-11-07)

- 決定どおり実装した。ワンタイムパスワードは同時に3件まで有効とし、失敗は有効な全件の試行回数に加算する。
- ログインの回数制限は、IP ごと(10回/分)と IP と ID の組み合わせごと(5回/分)とし、ID 単独では制限しない。
- 復旧のメール送信の失敗は、応答では知らせずログに記録する(ID の有無を応答時間から推測されないため)。
- 残るリスク: 第三者が他人の ID で誤入力を繰り返すと、本人の有効なワンタイムパスワードを失効させられる
  (analyze の R1)。

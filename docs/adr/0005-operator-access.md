# ADR-0005: 運営者による利用者データへのアクセス

- **Status**: 提案中
- **Date**: 2026-11-07

## 背景

憲章の原則 II と FR-044 は、運営者による利用者データへのアクセスを必要な場合に限定し、すべて記録することを
求めている。暗号鍵はサービスが管理するため(ADR-0002)、鍵と DB の両方に触れられる者は内容を読める。

## 決定

- アプリに運営者向けの閲覧機能や管理画面を設けない。
- 本番 DB の接続情報と暗号鍵(`DATA_ENCRYPTION_KEYS`)は、別々の権限で管理する。両方を持つ者は最小限にする。
- 本番 DB への接続と、鍵の参照は、ホスティング先の監査ログで記録する。この機能を持つことをホスティング先の
  選定条件とする(Phase 9)。
- 障害対応でデータに触れた場合は、日時、対象、理由を `docs/operations/production-access.md` に記録する。

## 検討した代替案

- アプリ内の管理画面と、アプリでのアクセス記録: 閲覧経路そのものが攻撃対象になり、実装も増える。
- 利用者が鍵を持つ方式: 共有と復旧が機能しない(ADR-0002 で不採用)。

## 影響

障害の調査で利用者のデータを確認しにくくなる。ログには日記の内容を出力しないため(憲章の原則 III)、
調査はエラーの種類と要求の経路から行う。
